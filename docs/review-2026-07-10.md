# Pre-implementation protocol review

Date: 2026-07-10.

## Outcome

The protocol required material changes before implementation. The reviewed
version is 0.2. The original correctness-dependent transition design must not be
implemented.

## Findings and resolutions

### Correctness-dependent scenes created an oracle

An observer can learn the legitimate scene sequence without learning exact
clicks. If a candidate stage produces the known next scene, the attacker learns
that stage independently of the rest of the credential.

Resolution: every attempt always displays the same account cue sequence and only
the complete chain is evaluated.

### The 58-bit figure counted cells that cannot be enrolled

The original calculation assumed all 384 geometric cells were equally usable.

Resolution: configured space is calculated from each manifest's actual eligible
cell count. Effective strength is reported only from measured distributions.

### Responsive behavior was underspecified

A 24 by 16 grid cannot maintain adequate target size on arbitrary mobile screens.

Resolution: protocol version 1 is desktop-first with a 1152 by 768 minimum scene
area and a frozen 3:2 contain-rendered derivative. Mobile requires a new policy.

### Shielded-mode leakage was too vague

The action remains observable, and repeated marker overlays rapidly intersect
location candidates.

Resolution: specify a 12 by 8 overlay with eight balanced markers, treat actions
as disclosed, and measure one, two, and three observations. No “shoulder-surfing-
proof” claim is allowed.

### Unknown-account behavior could enumerate users

Stable real cue scenes but random or missing unknown-account scenes would expose
account existence.

Resolution: return stable keyed synthetic cue sequences and perform dummy
Argon2id work with the same public behavior.

### Hotspot research conflicted with secret-free telemetry

The research plan required cell distributions while the threat model prohibited
collecting cells.

Resolution: use unlinkable aggregate scene/cell/action counters with no account,
participant, attempt, session, timestamp, or network identifier. Observation
targets are ephemeral consented lab credentials.

Aggregate marginals cannot measure cross-stage correlation. Full-chain guess
modeling is allowed only through a separately consented dataset of revoked,
study-only chains stripped of participant and performance linkage. Without it,
claims are limited to configured space and marginal hotspot behavior.

### Encrypted metadata needed an explicit trust consequence

Shielded verification needs server access to enrolled cells, so a hash alone is
insufficient.

Resolution: retain Argon2id/HMAC verification and separately authenticated-
encrypt the canonical credential with purpose-separated keys. State clearly that
a database-plus-encryption-key compromise reveals paths.

### Image provenance and immutability were not complete

“Licensed scenes” did not define acceptable evidence, derivative handling, or
non-copyright rights.

Resolution: formalize a 48-scene CC0 pack, per-file evidence, canonical hashes,
human-reviewed 3:2 derivatives, eligible-cell masks, and signed pack freeze.

### Application-origin attacks were missing

XSS, third-party scripts, clickjacking, CSRF, session fixation, and research
export authorization can defeat or expose the protocol.

Resolution: target OWASP ASVS 5.0 Level 2 and add a same-origin, self-hosted web
security baseline.

### German research-data obligations needed detail

Pseudonymous research data remains personal data when it can be relinked.

Resolution: separate authentication and research identities, minimize fields,
document the legal basis and controller, support withdrawal and deletion where
applicable, define retention before recruitment, and obtain institutional ethics
and data-protection review before recordings or formal data collection.

## Decisions retained

- five stages;
- exact 24 by 16 credential cells;
- eight discrete directions;
- guided enrollment windows;
- direct and shielded presentations of the same credential;
- Argon2id with salt plus a separate verifier HMAC;
- separately encrypted metadata for shielded verification;
- password and passkey alternatives;
- React/Vite frontend, Spring Boot API, PostgreSQL, Redis, and Docker Compose.

## Implementation authorization gate

Implementation may begin from protocol version 0.2. Formal participant
recruitment remains blocked until protocol test vectors, scene-pack pilot,
security verification, power analysis, consent materials, ethics review, and
data-protection review are complete.
